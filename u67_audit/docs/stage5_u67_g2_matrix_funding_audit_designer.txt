PART 2 - FUNDING ARITHMETIC AUDIT (independent re-check of docs/FUNDING_MODEL_REVIEW.txt; analytical only; no measured funding, no engine change)
A. Engine facts (verified in both engines): cost_fraction = 0.0015 x (1 + exit/entry) + 0.00010 x bars_held x 0.5; net_r_s3 = gross_r - cost_fraction / risk_pct. So funding is ALWAYS a cost, computed on entry notional, bars_held x 0.5 events, no timestamp, no sign, no direction. Per-event rate implied: 0.00010 (0.01% per 8h).
B. Event count: with events at 00/08/16 UTC and entry at a 4H candle open, a holding of n bars spans 4n hours. n=30 -> exactly 15 events for every entry alignment (verified by enumeration over the six 4H opens); n=6 -> exactly 3; n=15 -> 7 or 8 (the Stage 4 table used 7.5). A position closed by SL/TP inside a bar pays only for events before the exit instant; bars_held is a bar count, so the event count of a short trade can differ by one from bars/2.
C. Formula check: real funding effect in R = sign x events x r / risk_pct, sign = +1 for short and -1 for long when r > 0 (long pays, short receives), reversed when r < 0. Flat model effect = -0.00005 x n / risk_pct for BOTH sides.
D. Re-check of the Stage 4 table: all 81 cells (9 rows x 9 values) recomputed independently: 0 arithmetic mismatches (tolerance 0.01R); signs correct (short +, long - for positive funding; reversed for negative). No arithmetic or sign error found. Labelling weakness found: column "ev" showed 7.5 for n=15 (real: 7 or 8; effect +-0.03R at 1.5% risk, r=0.10%); and the document did not show the MODEL ERROR (real minus flat). Corrected view below (30 bars, exactly 15 events):

E. Interpretation: U67-L (long): engine too optimistic whenever real funding > +0.01%/8h (e.g. -0.90R at +0.10%, 30 bars, 1.5% risk); too pessimistic when funding is negative. U67-S (short): engine pessimistic under positive funding, too optimistic under negative funding (squeezes: -0.20R at -0.03%). Sign of the error is regime-dependent and is not known for the actual sample.
